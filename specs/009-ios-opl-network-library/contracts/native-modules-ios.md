# Contract: iOS Native Modules

The TurboModule contract (method names, argument/return shapes) is defined once, cross-platform, by the TypeScript spec files under `mobile/src/native/specs/*.ts` and is **not duplicated or forked** for iOS — see `specs/006-android-opl-network-library/contracts/native-modules.md` and `specs/008-android-forge-essentials/contracts/native-modules.md` for the authoritative method-by-method contract. This document records only what's specific to the Swift-side implementation: which native class answers each spec, and any implementation note that isn't visible from the TS contract alone.

| TurboModule spec (`mobile/src/native/specs/`) | Swift implementation (`mobile/ios/OplForgeMobile/`)   | Kotlin counterpart (unchanged, for reference)          | Implementation notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `NativeLibraryModule.ts`                      | `Library/LibraryModule.swift`                         | `library/LibrarySelectionModule.kt`                    | `selectLibrary()` presents `UIDocumentPickerViewController` (research.md R2) instead of `ACTION_OPEN_DOCUMENT_TREE`; `clearAppData()` has no iOS equivalent to `ActivityManager.clearApplicationUserData()` — implemented as an explicit in-app wipe of the app's own `UserDefaults`/Keychain/Core Data store (App Store review does not allow an app to relaunch itself the way Android's OS-level restart works), so the caller-facing behavior ("everything is reset") is preserved even though the mechanism differs.                                                                                                                                                                              |
| `NativeCatalogModule.ts`                      | `Catalog/CatalogScanModule.swift`                     | `catalog/CatalogScanModule.kt`                         | Folder-walk logic ports directly (`FileManager.contentsOfDirectory` in place of `DocumentFile.listFiles()`); art-matching normalization (`<GAMEID>_COV[2].png`) is pure string logic, ports unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `NativeSharingModule.ts`                      | `Sharing/SharingModule.swift` + `Sharing/Smb/*.swift` | `sharing/SharingSessionModule.kt` + `sharing/smb/*.kt` | Adds the `'suspended'` session state (data-model.md) with no Android counterpart; `startSharing(shareName)` binds an `NWListener` on port 1445 (research.md R5) instead of a `ServerSocket` inside a Foreground Service.                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `NativeTransferModule.ts`                     | `Transfer/TransferQueueModule.swift`                  | `transfer/TransferQueueModule.kt`                      | Durable queue persisted the same way as the catalog index (Core Data/SQLite, research.md Storage); no `WorkManager` equivalent — in-process `URLSession` background configuration is used for network downloads specifically (Essentials/Art Sync fetches), which _does_ have real iOS background-continuation support (unlike the SMB listener) since it's a bounded, system-managed transfer, not an open-ended listening socket.                                                                                                                                                                                                                                                                    |
| `NativeEssentialsModule.ts`                   | `Essentials/EssentialsModule.swift`                   | `essentials/EssentialsModule.kt`                       | HTTP calls (Internet Archive metadata, libretro-thumbnails tree lookups — including the `Named_Boxarts` subtree-by-sha fix already discovered on Android) use `URLSession`; concurrency-limiting for the ~325-item accessibility/art-enrichment pass MUST use a Swift structured-concurrency equivalent of a suspending semaphore (e.g. bounded `TaskGroup` batches or an `AsyncSemaphore`-style actor) — never a thread-blocking primitive, mirroring the exact lesson already learned and fixed on Android (a `java.util.concurrent.Semaphore` inside a coroutine starved the whole app's IO dispatcher; the Swift equivalent mistake would be blocking a `DispatchQueue` thread pool the same way). |
| `NativeDiagnosticsModule.ts`                  | `Diagnostics/DiagnosticsModule.swift`                 | `diagnostics/DiagnosticsModule.kt`                     | Folder-existence/creation checks port directly; the 20s timeout guard already added on Android (`withTimeoutOrNull`) has a direct Swift equivalent via `Task` + `withThrowingTaskGroup`-based timeout racing, kept for the same reason (never let the UI spin forever on a stalled scan).                                                                                                                                                                                                                                                                                                                                                                                                              |
| `NativeArtSyncModule.ts`                      | `Art/ArtSyncModule.swift`                             | `art/ArtSyncModule.kt`                                 | The ZIP64 central-directory parser and HTTP range-request fetch logic (`ZipCentralDirectoryParser.kt`/`RemoteZipArtIndex.kt`) are pure byte-manipulation and HTTP logic with zero Android-specific dependencies — direct, close-to-line-for-line Swift port, including the same test fixtures (real bytes from the archive.org ZIP, not synthetic).                                                                                                                                                                                                                                                                                                                                                    |

## Event emitters (native → JS)

`onSharingSessionEvent`, `onCatalogScanEvent`, `onTransferQueueEvent`, `onArtSyncEvent` — same event names and payload shapes on iOS as Android (TurboModule event emitters are already cross-platform via Codegen); Swift implementations call the same generated emitter methods Kotlin does via `TypedEventEmitter`'s equivalent generated base class, no new JS-side listener code needed in `mobile/src/native/*.ts` wrappers.
